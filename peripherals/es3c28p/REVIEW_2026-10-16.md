# ES3C28P review and refactor — 2026-10-16

Scope: firmware under `src/` and `lib/`, USB Python client, media converter,
Arduino/PlatformIO build configuration, bench sketches, and tests. This review
was made on top of the existing uncommitted navigation/panning changes; those
changes were preserved. The three design plans and shared protocol headers
were hash-checked unchanged. No Jetson production code, board pins, protocol
bytes, tab layout, or voice feature was changed by this review. The overlong
default Settings label was shortened to permit startup.

## Findings and fixes

| Priority | Finding and trigger | Resolution and evidence |
| --- | --- | --- |
| P1 | The shipped Settings page contained `Tap SET tab to calibrate` (24 characters), but `setPages()` rejects fields of 24 or more bytes. Short-circuit startup therefore never called graphics initialization. | Shortened the label to `Tap SET to calibrate`. Moved the actual default table to `src/DashboardConfig.h` and its existing validation policy to portable `PageConfig.h`; tests validate the production table and reproduce rejection of the former label. |
| P2 | Saving calibration removed the old file before opening/writing its replacement; a full card or failed write lost the saved calibration. A positive short write was also reported as success. | `CalibrationStore.h` writes and reads back a temporary record before rotating the previous file to `.bak`. Boot prefers the primary and falls back to the backup. Fault-injection tests fail each write/remove/rename stage, retry, and simulate interruption after rotation. Strict bounded parsing rejects oversized integers, missing fields and trailing junk without `sscanf` integer conversion overflow. |
| P2 | `openRead()` remounted the entire SD filesystem on an ordinary missing-file error. A missing splash while WAV playback retained a File could invalidate that reader, as well as stall the UI during a needless remount. | Missing files now fail without unmounting other readers. Explicit `remount()` requires callers to close all files first. Root-directory diagnostics stop after 32 entries. SD replacement requires an explicit safe remount or restart; automatic remount is no longer hidden inside file open. Physical card/error behavior still needs bench validation. |
| P2 | BMP height `INT32_MIN` was negated in signed arithmetic; pixel extent addition could wrap and the pixel offset could point into the DIB. | Portable `BmpLayout.h` validates the actual file extent using 64-bit arithmetic and an unsigned height magnitude, including DIB/pixel separation. Tests cover top-down/odd-width images, truncation, INT32_MIN, overlapping offsets and overflow values. Converter applies the same header-separation rule. |
| P2 | Python requests could time out despite having a complete matching reply buffered behind an incomplete record, because the parser was never polled during idle reads. | Control requests poll at 50 ms intervals inside the original deadline; playback also polls on EAGAIN. A real pseudo-tty regression failed before the fix and passes afterward, with exactly one STATUS request and no command replay. |
| P3 | After a successful panning allocation followed by worker-creation failure, a startup retry that fell back to small buffers retained the large capacity metadata. Current session validation limits exposure, but the decoder's allocation-capacity invariant was false. | Startup allocation/cleanup moved to `VideoBuffers.h`. Every free clears pointer and capacity together; every allocation sets its actual capacity. Tests inject failure at all eight allocation positions and retry after cleanup with the optional upgrade failing. |
| P3 | WAV metadata traversal was bounded only by total file size, permitting a large number of tiny chunks to occupy the UI loop before playback. | Extracted `WavHeader.h`, with at most 256 chunks and chunk headers starting within the first 64 KiB. Existing mono PCM8, 8–16 kHz support is unchanged. Portable tests cover valid padded/extended chunks, malformed sizes/rates/formats and the scan limit. |
| P3 | Calling USB `begin()` twice allocated another set of queues and another task. The production setup calls it once, but the reusable service did not enforce that invariant. | Successful initialization is now idempotent via the existing task handle. |

The P1 startup failure and the listed P2/P3 findings are fixed. Hardware timing
and every possible cross-task interleaving are not proven by this source review.

## Refactoring and ownership

The former 1,211-line graphics source is divided into:

- `es3Graphics.cpp`: initialization, dashboard text, brightness, tabs and navigation.
- `es3GraphicsAssets.cpp`: SD BMP/RGB565 rendering.
- `es3GraphicsTouch.cpp`: touch mapping, calibration capture and calibration UI.
- `es3GraphicsStream.cpp`: camera/whole-map/panning presentation and freshness.

`GraphicsInternal.h` exposes the single panel instance only to these implementation
files. This is a source-organization refactor, not a new task or additional display
owner. The existing public graphics API is retained. Portable validation and
resource policy are extracted where they permit meaningful failure tests; the
stateful renderer was not rewritten into a new framework.

| Owner | Exclusive work | Communication |
| --- | --- | --- |
| USB task, core 0, 8 KiB stack | Serial RX/TX, mux parser, control session and partial TX | One-slot command/response queues with epochs; short video-state mutex operations |
| JPEG worker, core 0, 8 KiB stack | One JPEG decoder, leased input/output buffers | Decode outside mutex; publish only for matching token/visibility epoch |
| Arduino loop | TFT/SPI, touch/codec I2C, SD files, WAV I2S, UI and retained image leases | USB application commands; bounded image strips; video-state snapshots under mutex |

Reviewed the bounded event queue, cumulative credits, source exclusion, timeout
arithmetic, session replacement, visibility cancellation, same-kind panning
supersession, retained buffer lifetimes and PRESENTED semantics. Existing tests
cover these paths and were retained. The prior ABORT(Ok) and parser timeout fixes
are already present in the shared headers; this review did not alter them.

Image memory remains 958,464 bytes with panning, with a 1,265,664-byte startup peak;
whole-frame fallback remains 438,272 bytes. Allocation now stops early on failure.
No new task, runtime image allocation, or larger image/strip buffer was introduced.
Worker stack reservations remain 8 KiB each; real stack high-water marks require
hardware measurement. Media helpers use bounded automatic arrays and no heap.

## Validation

Baseline `tests/run_tests.sh` passed before edits (38 Python tests plus native
protocol/state/calibration tests). The expanded suite adds C++11/C++17 resource, production page-configuration
and media-header tests and a Python pseudo-tty timeout regression (39 tests).

Reproduce from the repository root:

```sh
peripherals/es3c28p/tests/run_tests.sh
peripherals/es3c28p/tests/run_sanitizer_tests.sh
# In l4t-ml-gpio:latest, with its pinned JPEGDEC source and Pillow:
peripherals/es3c28p/tests/run_decoder_tests.sh
peripherals/es3c28p/build_and_upload.sh
ES3_USB_MODE=default peripherals/es3c28p/build_and_upload.sh
```

The sanitizer script covers calibration, video state, map surfaces, pan raster,
allocation/persistence failures, and BMP/WAV headers with ASan + UBSan. Decoder
fixtures include 512x384 and odd-sized 4:2:0 backgrounds and 320x32 strips.
JPEGDEC itself uses ASan only for the previously documented upstream arithmetic
and alignment behavior; our decoder wrapper/tests also use UBSan.

The BMP converter reproduces the checked-in splash.rgb565 byte-for-byte from
splash.bmp. Shared-header parity, preserved-plan hashes and diff whitespace are
checked separately. All checks above passed. Final Arduino ESP32 3.2.0 / JPEGDEC 1.8.4 builds in
`l4t-ml-gpio:latest` passed with `--warnings all` and no warnings:

| USB mode | Before: flash / static RAM | After: flash / static RAM |
| --- | ---: | ---: |
| HWCDC | 559,370 / 54,740 bytes | 543,610 / 54,740 bytes |
| TinyUSB | 595,914 / 73,900 bytes | 580,190 / 73,900 bytes |

The before figures are the recorded 2026-10-14 panning builds. Static RAM and
PSRAM requirements are unchanged; flash decreased by 15,760 and 15,724 bytes
respectively. The source split was also checked against its original file:
touch/calibration and streaming function bodies are unchanged apart from the
panel object's implementation name. Shell scripts pass `bash -n`. Converter
checks reject overlapping/out-of-file BMP offsets without producing an output.

## Remaining physical checks and limits

- No board was flashed. Recheck calibration SAVE/reboot and backup recovery on
  an actual card, and missing splash/WAV files during playback. FAT rename and
  flush cannot guarantee recovery from every power-loss/card-controller failure.
- SD calls, I2C calls and SPI transfers remain synchronous. Bounded software
  work does not establish a hard latency bound for failing hardware. Check touch
  responsiveness, I2S underruns and stack/heap minima during an extended soak.
- Exercise camera -> map -> panning -> hidden/calibration transitions while
  decoding; disconnect/reconnect each USB mode and force optional PSRAM failure.
- Verify marker/attribution behavior and measure actual USB throughput, redraw
  cadence and tearing. No performance improvement is claimed from the refactor.
- Linux Arduino CLI builds are the verified build path. Windows and PlatformIO
  configuration were inspected; their execution remains untested here.
